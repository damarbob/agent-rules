# Web Design Guide

> Shared rule from [agent-rules](https://github.com/damarbob/agent-rules). Do not edit this copy. Change it in that repository and run sync. Repository-specific rules belong in a separate file in this folder.

Pages built by AI converge on one look. Visitors recognise it and discount the product behind it. Use this guide when you build or restyle a page, and treat it as a list of defaults to question, not a ban.

## The formula to avoid

This is the hero that most generated landing pages open with:

1. A small label or badge above the headline.
2. A large centred headline.
3. A subtitle under it.
4. Two buttons, one filled and one outlined.
5. A glow, gradient or blurred shape behind it.

One of these is fine. The full stack is the tell. Start the page from what the visitor needs first, which might be a product screenshot, a code sample, a number with its context, or the answer to a question.

## Other tells

- An eyebrow badge above every section heading.
- Sections that share one rhythm, such as a heading, a one-line subtitle, three equal cards with icons, and then the same again.
- Parallel copy, where every card has a two-word heading and a sentence of the same length.
- One component-kit look, with the same corner radius, shadow and gradient on everything.
- A purple-to-blue gradient, glassmorphism or glowing borders as the default accent.
- Stock icons in circles standing in for real visuals.
- Placeholder social proof, such as "Trusted by teams everywhere" over grey logos, invented counters and fake testimonials.
- A centred text block under every heading, whatever the content.
- Emoji used as icons.

## What to do instead

- Let the content decide the layout. A comparison is a table, a process is a diagram, and a feature with a screen is a screenshot beside its explanation.
- Vary structure, width, alignment and density from one section to the next, so no two sections share a template. Mix full-bleed and narrow, left-aligned and centred, dense and sparse.
- Use real material, such as real screenshots, real code and real numbers with their context.
- Choose type, colour and spacing for this product. Don't accept the first default.
- Write the copy for each section separately, and let the lengths differ.
- Look at a site whose sections change shape as you scroll, such as konghq.com, before settling on a layout.

## Before handing over

1. Compare consecutive sections in the markup. Do any two share a structure?
2. Count the badges, gradients and glows.
3. Check that every number, logo and testimonial is real.
4. Try the headline left-aligned. Does the page still make sense?
